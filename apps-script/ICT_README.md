# Заявки по ИКТ (этап 1): `IctRequests.gs`

Учитель отправляет заявку с `help.html`, заместитель директора по ИКТ работает с заявками на `ikt.html`, инженер — в боте MAX. Как устроена часть бота — в `max-worker/README.md`, раздел «Заявки по ИКТ».

## Где хранятся данные

- **Заявки** — в отдельной закрытой таблице «СОШ20 — Заявки ИКТ», лист `Заявки_ИКТ`. Рабочая таблица (`SPREADSHEET_ID`) открыта сайту по ключу API, поэтому заявки туда **не** пишутся. Закрытую таблицу скрипт создаёт сам при первой заявке (на Диске владельца скрипта) и запоминает её в свойстве `ICT_SPREADSHEET_ID`. Не открывайте к ней доступ по ссылке.
- **Фото** — в папке Диска «СОШ20 — фото заявок ИКТ» (свойство `ICT_PHOTOS_FOLDER_ID`, папка создаётся сама). Сайт показывает фото заму только через вход по PIN, ссылки на Диск на страницу не попадают.
- **Помещения** — необязательный лист `Помещения` в рабочей таблице: первая колонка — названия помещений без уроков (библиотека, медкабинет…). В нём только названия, поэтому он может быть открытым.

Колонки `Заявки_ИКТ`: ID, Создана, Тип (tech|question), Учитель, Кабинет, Устройство/Тема, Описание, Срочность (red|yellow|white), Фото, Исполнитель (engineer|ikt), Статус, Комментарий исполнителя, Перенесено_на, Обновлена, Закрыта, Учитель_уведомлён (да/нет — дошёл ли ответ или результат в MAX), История (JSON: кто, когда, что изменил — учитель, зам по ИКТ или инженер), Код_MAX (код учителя для привязки MAX; один на учителя).

Статусы: `new`, `in_work`, `done`, `not_done`, `cannot_fix`, `postponed`, `transferred`, `answered`. Закрытыми считаются `done` и `answered`. «Нет возможности» (`cannot_fix`) остаётся открытой и переходит заму по ИКТ: нужно что-то купить или отдать в ремонт.

## Свойства скрипта

| Свойство | Кто задаёт | Что это |
|---|---|---|
| `IKT_PIN` | вы, вручную | вход заместителя по ИКТ на `ikt.html`, 6–8 цифр, не совпадает с `ADMIN_PIN` |
| `STAFF_PIN` | зам по ИКТ на `ikt.html` → «Настройки» | общий PIN учителей для отправки заявок, 4–8 цифр; не может совпадать с `ADMIN_PIN`, `LATE_PIN`, `IKT_PIN` |
| `ICT_SPREADSHEET_ID` | создаётся само | закрытая таблица заявок; можно указать свою |
| `ICT_PHOTOS_FOLDER_ID` | создаётся само | папка с фото; можно указать свою |
| `ICT_SECRET` | вы, вручную | общий секрет с ботом (то же значение — секрет Cloudflare `ICT_SECRET`), не короче 16 символов; без него бот заявки не видит |
| `BOT_URL` | уже есть | адрес бота; по умолчанию `https://school-schedule.mark441302.workers.dev` |

## Защита

- Неверный PIN: после 20 ошибок за 15 минут приём (или вход зама) закрывается на 15 минут для всех. Счётчики учителей и зама раздельные.
- С одного учителя — не больше 10 заявок в час. Учитель — только из листа `Учителя`, кабинет — из расписания или листа `Помещения`, описание до 1000 символов, фото до 5 МБ (JPEG/PNG/WebP; сайт сам сжимает до 1600 px и убирает данные камеры).
- Сессия зама живёт 12 часов с момента входа, хранится в CacheService под ключом `ikt:`, поэтому токен зама не открывает панель замен, а токен панели — страницу зама.

## Установка (ручные шаги)

1. Скопировать `IctRequests.gs` в проект Apps Script и обновить `ManagementExtensions.gs` (в `doPost` добавлена строка, которая передаёт действия `ictRequest` и `ikt…` в новый файл).
2. Свойства скрипта → добавить `IKT_PIN` (6–8 цифр) и `ICT_SECRET` (длинная случайная строка, то же значение — в секрет бота).
3. Развернуть **новую версию** веб-приложения (адрес не меняется). При первом запуске Google попросит разрешение на создание таблицы и папки на Диске — разрешить.
4. Открыть `ikt.html`, войти по `IKT_PIN`, в «Настройках» задать PIN для учителей и сообщить его учителям.
5. По желанию: лист `Помещения` в рабочей таблице; QR-наклейки — `help-qr.html` → «Печать» (листы самоклеящейся бумаги A4, 12 наклеек 70×74 мм).

Проверка: `node tests/ikt-requests.js`, `node tests/qr.js`, `node tests/max-ict.mjs`.
