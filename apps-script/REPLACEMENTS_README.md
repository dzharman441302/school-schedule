# Замены: только переданные уроки, проверка за неделю

Обновление 01.10.2026. Основное расписание, логика двух классов, публикация ученикам и ротация ТВ этой правкой не изменяются.

## Установка поверх версии с кнопкой «Замены»

Сохраните копии текущих файлов. В существующем проекте Google Apps Script полностью замените:

- `ScheduleModel.gs`
- `ReplacementJournal.gs`
- `ReplacementPanel.html`

Остальные файлы, ID таблицы, PIN и настройки доступа оставьте прежними. Все три файла необходимо обновить вместе.

Сохраните проект. «Развернуть» → «Управление развертываниями» → действующее развертывание → карандаш → «Новая версия» → «Развернуть». Затем обновите панель. Не создавайте новый адрес панели.

Обновление исходников в GitHub не меняет само по себе опубликованную версию Google Apps Script. Веб-панель должна быть развернута заново указанным способом.

Для первоначальной установки по-прежнему нужны все семь файлов из папки `apps-script`: `Admin.html`, `Code.gs`, `PublishWarnings.gs`, `ManagementExtensions.gs`, `ScheduleModel.gs`, `ReplacementJournal.gs`, `ReplacementPanel.html`. Эта правка предполагает уже установленную предыдущую версию.

## Что попадает в журнал

Только назначение принимающего учителя, когда урок другого преподавателя передан ему. Снятие исходного урока не создаёт отдельной строки. Например: сняли пять уроков, из них два передали другим учителям — две записи для проверки, а не семь.

Простые отмены, смены кабинета, дополнительные уроки без исходного учителя и перестановки собственных уроков не требуют решений в разделе «Замены». Сохранившиеся старые строки такого типа не удаляются из служебной таблицы, но не показываются в рабочем журнале, не учитываются в часах и не увеличивают счётчик ожидания. История решений остаётся доступна.

Подгруппы сопоставляются с выбывшими преподавателями, а не с последней фамилией в классе. При неоднозначности нужно выбрать исходного учителя. Расхождения с ручными изменениями для учеников требуют проверки. Ручная запись требует указать другого исходного преподавателя и пояснение.

Один принимающий учитель на одном номере урока — одна запись. Два класса в одном слоте не дают два часа автоматически. Сохраняется явное подтверждение количества часов и обязательное пояснение для нестандартного случая. Факт проведения и обоснованность учёта подтверждает администратор, а не программа.

## Работа в течение недели

После публикации расписания записи сохраняются со статусом «Проверить», но окно учёта больше не открывается автоматически. У кнопки «Замены» отображается количество ожидающих решений за неделю выбранной даты.

Нажатие «Замены» открывает всю неделю: понедельник–воскресенье, включая переход через границу месяца или года. Вкладка «Проверить неделю» содержит записи всех её опубликованных дней, сгруппированные по датам. Есть переход на предыдущую, текущую и следующую неделю, фильтр учителя, журнал, сводка, печать и CSV подтверждённых записей.

Выберите «Учесть», «Не учитывать» или оставьте «Проверить». Затем нажмите «Сохранить решения за неделю». Сохраняются только изменённые строки, в том числе скрытые текущим фильтром. «Применить рекомендации» меняет только видимые ожидающие строки формы и ничего не подтверждает до сохранения.

За один раз можно просмотреть и сохранить период до 31 дня. Недельный просмотр является исходным режимом. Для истории решений или ручного добавления указывается конкретная дата внутри периода.

## Напоминание в конце недели

Начиная с пятницы по московской дате в открытой панели показывается небольшой блок «Проверьте замены за неделю» с кнопкой «Открыть неделю». Это не всплывающее окно и не блокировка публикации. Он появляется только при ожидающих решения передачах уроков.

После проверки всех записей недели напоминание исчезает. Если неделю не закончили, она остаётся доступна и после выходных; сначала предлагается самая ранняя непроверенная неделя. Выбор будущей даты расписания не вызывает напоминание раньше пятницы. Состояние проверяется после загрузки дня, публикации, возврата на вкладку и раз в пять минут, пока панель открыта.

При закрытом браузере напоминание не отправляется: это функция самой панели, без отдельной рассылки, push-уведомлений или триггеров. Сбой учёта после публикации отображается отдельным предупреждением, без автоматического открытия окна.

## Повторные публикации, восстановление и сохранение

Неизменённые передачи сохраняют подтверждения. Изменённые требуют новой проверки, удалённые исключаются из суммы, действия остаются в истории. Обычная и отложенная публикация и откат используют общий механизм учёта.

Перед сохранением всей недели проверяются версии всех изменяемых дней. Если хотя бы один день устарел, ни одно решение не перезаписывается. При ошибке записи изменяемые дни помечаются как незавершённые и не входят в сумму до повторной проверки.

«Восстановить период» работает без перепубликации расписания: предпочтение отдаётся сохранённой исходной/итоговой сетке `Учителя_сайт`; при отсутствии снимка используется архив правок с текущим основным расписанием и пометкой необходимости сверки. Старые расчётные часы не утверждаются автоматически. Дни без сохранившихся источников нельзя считать нулевыми только по отсутствию записей.

Служебные листы: `Журнал_замен`, `Замены_публикации`, `Замены_аудит`. Не удаляйте их. Скрытие листа не ограничивает доступ: права задаются в Google-таблице. Общий PIN не позволяет определить конкретного сотрудника, поэтому в аудите используется роль «Администратор панели».

## Ограничения и проверка

Рекомендации основаны на сохранённой сетке и сопоставлении назначений внутри одного дня. Междневные переносы и договорённости, отсутствующие в данных, проверяются вручную. Журнал не является автоматическим доказательством проведения урока или основанием начисления оплаты.

Проверки: `node tests/schedule-regression.js` и `node tests/schedule-weekly-review.js`. В сценариях проверяются реальные передачи, отмены, подгруппы, два класса, повторная публикация, версии решений, ошибки записи, восстановление, недельные границы и напоминание с пятницы. Интерфейс проверяется отдельно в Chromium на модельной таблице; после установки нужна сверка одного рабочего дня в действующем Apps Script.
