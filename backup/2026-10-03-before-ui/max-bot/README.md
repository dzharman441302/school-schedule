# MAX-бот «СОШ №20 · Расписание»

Первая тестовая версия работает через **Long Polling**. Это сделано специально для безопасного пробного запуска без отдельного webhook-домена. После проверки сценариев production-версию лучше перевести на HTTPS Webhook.

## Что умеет версия 0.1

- первый запуск: выбор роли **Учитель** или **Ученик / родитель**;
- учитель выбирается из списка в том же порядке, что и в листе `Учителя`;
- ученик/родитель выбирает класс;
- главное меню: **Сегодня**, **Завтра**, **Изменения**, **Оповещения**, **Профиль**;
- расписание берётся из тех же Google Sheets, что и сайт школы;
- учителю показывается опубликованная сетка `Учителя_сайт`, а при отсутствии публикации — основное расписание;
- ученику показывается основное расписание с наложенными изменениями из листа `Изменения`;
- после изменения опубликованных данных бот автоматически присылает информацию только затронутому пользователю;
- учитель получает кнопку **✓ Увидел**; нажатие записывается в существующую систему `Просмотры_учителей` через Apps Script;
- новые активные школьные оповещения автоматически рассылаются нужной аудитории;
- профиль пользователя и служебное состояние хранятся локально в `data/state.json`;
- токен MAX хранится только в `.env` и не попадает в GitHub.

## Запуск на VPS через Docker

```bash
cd /opt
sudo git clone https://github.com/dzharman441302/school-schedule.git school20
cd /opt/school20/max-bot
cp .env.example .env
nano .env
```

В `.env` вставьте токен MAX:

```env
BOT_TOKEN=ВАШ_ТОКЕН_MAX
```

Остальные значения уже настроены на текущий сайт и Apps Script. Затем:

```bash
sudo docker compose up -d --build
sudo docker compose logs -f --tail=100
```

При нормальном старте в логах появится примерно:

```text
Bot connected: ...
School data: 36 teachers, 21 classes
Long polling started
```

После этого откройте бота в MAX и отправьте `/start`.

## Команды

- `/start` — главное меню;
- `/today` — расписание на сегодня;
- `/tomorrow` — расписание на завтра;
- `/changes` — только изменения;
- `/profile` — профиль.

Основной интерфейс построен на кнопках, поэтому команды запоминать не требуется.

## Как работают автоматические уведомления

Бот раз в `CHECK_SECONDS` сравнивает опубликованные данные с предыдущим состоянием конкретного пользователя. При первом запуске текущая публикация считается базовой и задним числом не рассылается. Следующее изменение данных вызывает персональное уведомление.

Если ранее опубликованные изменения полностью сняты, бот тоже сообщает, что снова действует основное расписание.

## Обновление

```bash
cd /opt/school20
git pull
cd max-bot
sudo docker compose up -d --build
```

## Остановка

```bash
sudo docker compose down
```

## Данные и резервирование

Профили пользователей находятся в `max-bot/data/state.json`. Каталог смонтирован с хоста, поэтому пересоздание контейнера данные не удаляет. Файл желательно включить в обычное резервное копирование VPS.

Не публикуйте `.env` и не вставляйте токен в исходный код.

## После теста

MAX рекомендует Webhook для production. После проверки интерфейса и сценариев переводим бот на HTTPS endpoint с проверкой `X-Max-Bot-Api-Secret`, а бизнес-логику профилей, расписания, подтверждений и рассылок оставляем прежней.
