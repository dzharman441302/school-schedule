# MAX-бот СОШ №20 на Cloudflare Workers

Production-вариант без VPS: Cloudflare Worker + D1 + MAX Webhook.

## Что умеет v0.4 (и v0.5 — заявки по ИКТ, см. ниже)

- Webhook MAX с проверкой `X-Max-Bot-Api-Secret`;
- объявления: кнопка «Объявления» показывает все действующие объявления, которые касаются пользователя (по 5 на странице, каждое открывается целиком с кнопкой-ссылкой и файлами); объявления с отметкой «Рассылка в бот» в панели приходят подписчикам один раз — по аудитории и, если указаны, только нужным классам; срочные — сразу, остальные — с 7:00 до 21:00;
- `GET /stats` — только суммарные числа без имён и id: сколько человек подписано, у скольких включены уведомления, сколько подписок на каждый класс; с `?audience=students&classes=9А,9Б` — сколько человек получат такое объявление. Эти числа показывает панель на вкладке «Объявления»;
- подписки: один пользователь может добавить до 6 классов и учителей (например, всех своих детей и себя как учителя) — кнопка «Мои подписки»; «Сегодня», «Завтра» и «Изменения» показывают всех сразу, уведомление приходит по каждому отдельно;
- в уведомлении класса первой строкой — во сколько приходить и во сколько закончатся уроки, если изменения это сдвигают («Приходить к 08:50 — к 2-му уроку (обычно к 08:00)»);
- звонки берутся из листов `Звонки` и `Звонки_даты`, как на сайте; в сокращённый день бот так и пишет;
- роли: учитель / ученик или родитель;
- выбор учителя из листа `Учителя`;
- выбор класса 5–11 из листа `Расписание`;
- кнопки Сегодня / Завтра / Изменения / Оповещения / Профиль;
- расписание читается из тех же Google Sheets, что сайт школы;
- учитель видит опубликованную сетку `Учителя_сайт`;
- ученик видит `Расписание` + лист `Изменения`;
- кнопка `✓ Увидел` записывает подтверждение в D1 и существующий Apps Script;
- каждую минуту Worker проверяет новые публикации (на сегодня и на две недели вперёд) и присылает ученикам класса и учителю уведомление об их изменениях;
- профили, подтверждения и состояние доставок хранятся в Cloudflare D1;
- токен MAX, webhook-secret и Google API key хранятся только как Cloudflare Secrets.

## Заявки по ИКТ (v0.5, `src/ict.js`)

Заявки хранятся в Apps Script (`apps-script/IctRequests.gs`), бот только читает и отмечает их по секрету `ICT_SECRET`. Сам скрипт в MAX ничего не пишет: после новой заявки или ответа зама он «стучит» в `POST /ict-ping`, и бот забирает свежий список. Кроме того, cron проверяет заявки раз в 5 минут днём (07:00–21:00) и раз в 15 минут ночью — по одному запросу к скрипту.

**Роли** (отдельно от подписок на расписание): `/role <код>` — по `ENGINEER_CODE` роль «инженер», по `IKT_CODE` — «зам по ИКТ»; `/role off` — снять. После 5 неверных кодов за час команда блокируется.

**Инженер** (только техника, всё в MAX):
- пятница 17:00 (если пятница выходная по листу `Календарь` — последний учебный день недели): «Заявки на субботу: N» и по сообщению на кабинет и устройство — по этажам, внутри по кабинетам, дубли одного кабинета и устройства вместе;
- новые заявки после пятничного списка и до конца субботы — сразу, с пометкой «Новая заявка»;
- кнопки ✅ Сделано · ❌ Не сделано · 🚫 Нет возможности · ➡️ Перенёс; после ❌ 🚫 ➡️ бот просит короткий комментарий (можно «Без комментария»), для ➡️ — дату (следующая суббота или своя); «Изменить отметку» — вернуть кнопки;
- 🚫 передаёт заявку заму по ИКТ (что купить или отдать в ремонт);
- фото — кнопка-ссылка `/ict-photo/<№>?s=<подпись>`: открывается только по подписанной ссылке;
- `/requests` — открытая очередь сейчас; суббота 18:00 — «Осталось без отметки: N».

**Зам по ИКТ** — уведомления с кнопкой «Открыть заявку» (`ikt.html#№`): «🔴 · Техника · от Фамилия И.О. · каб. 211 · Проектор · текст». 🔴 — сразу с 07:00 до 20:00; остальные — сразу в рабочее время (учебные дни 08:00–17:00), иначе в 08:00 следующего учебного дня. `/ikt_mode digest` — несрочные пачкой в 10:00 и 14:00 (🔴 всё равно сразу), `/ikt_mode instant` — обратно. Напоминания: вопрос без ответа дольше учебного дня; в первый учебный день недели в 08:30 — отчёт инженера за выходные (сделано, не сделано, что купить, перенесено), в 09:00 — заявки, которые инженер не отметил.

**Учитель** узнаётся не по подписке на расписание (на учителя может подписаться кто угодно), а по коду из формы заявки: после отправки на `help.html` кнопка «Получать ответы в MAX» открывает бота со ссылкой `?start=ikt-<код>`, или можно отправить `/link <код>`. Ответы зама приходят сразу, результат инженера — одним сообщением в первый учебный день недели в 08:00. Если учитель MAX не подключил, в заявке ставится «Учитель_уведомлён = нет» — зам видит это на `ikt.html`.

Повторов нет: каждое сообщение отмечается ключом `ict:…` в `bot_state` (старше 60 дней удаляются). Пока `ICT_SECRET` не задан, всё это выключено.

### Подключение (ручные шаги)

1. Секреты Worker: `npx wrangler secret put ICT_SECRET` (не короче 16 символов, то же значение — в свойство скрипта `ICT_SECRET`), `npx wrangler secret put ENGINEER_CODE`, `npx wrangler secret put IKT_CODE` (коды не короче 6 символов; их сообщают инженеру и заму лично).
2. Таблицы D1 (команды по одной, `--file` у нас не работает):
   `npx wrangler d1 execute school20-max --remote --command "CREATE TABLE IF NOT EXISTS ict_roles (user_id TEXT PRIMARY KEY, role TEXT NOT NULL, mode TEXT NOT NULL DEFAULT 'instant', updated_at TEXT NOT NULL)"`
   `npx wrangler d1 execute school20-max --remote --command "CREATE TABLE IF NOT EXISTS ict_links (user_id TEXT PRIMARY KEY, teacher TEXT NOT NULL, created_at TEXT NOT NULL)"`
   `npx wrangler d1 execute school20-max --remote --command "CREATE INDEX IF NOT EXISTS idx_ict_links_teacher ON ict_links(teacher)"`
3. `npx wrangler deploy`, затем `/health` должен показать версию 0.5.0.
4. Инженер пишет боту `/role <ENGINEER_CODE>`, зам — `/role <IKT_CODE>`.

## Бесплатный тариф

Для школьной нагрузки достаточно Workers Free + D1 Free. Отдельный VPS и домен для первого запуска не требуются. Cloudflare выдаст HTTPS-адрес `*.workers.dev`.

## Быстрый запуск через Cloudflare Dashboard

### 1. Создать аккаунт Cloudflare

Откройте Cloudflare Dashboard и войдите/зарегистрируйтесь.

### 2. Создать D1

Workers & Pages → D1 → Create database.

Имя:

`school20-max`

После создания скопируйте `Database ID`.

### 3. Создать Worker из GitHub

Workers & Pages → Create application → Import a repository.

Репозиторий:

`dzharman441302/school-schedule`

Root directory:

`max-worker`

Build command:

`npm install`

Deploy command:

`npx wrangler deploy`

Перед первым деплоем скопируйте `wrangler.toml.example` в `wrangler.toml` и замените `REPLACE_WITH_D1_DATABASE_ID` на ID созданной базы.

### 4. Создать таблицы D1

Через Cloudflare D1 Console выполните содержимое `schema.sql` целиком.

Либо через Wrangler:

`npx wrangler d1 execute school20-max --remote --file=./schema.sql`

`schema.sql` можно выполнять повторно: он добавляет недостающие таблицы и переносит в подписки класс или учителя из профилей v0.2. При обновлении с v0.2 выполните его **до** деплоя нового кода.

### 5. Добавить Secrets

В Worker → Settings → Variables and Secrets добавьте как **Secret**:

- `BOT_TOKEN` — токен MAX;
- `WEBHOOK_SECRET` — придуманный секрет 20–40 символов, только латинские буквы, цифры, `_` и `-`;
- `SHEETS_API_KEY` — Google Sheets API key из текущего сайта.

Обычные переменные уже прописаны в шаблоне:

- `SPREADSHEET_ID`;
- `APPS_SCRIPT_URL`;
- `SCHOOL_SITE_URL`;
- `TIME_ZONE`.

### 6. Проверить Worker

Откройте:

`https://<worker>.workers.dev/health`

Ожидаемый ответ:

`{"ok":true,"service":"school20-max-bot","version":"0.2.0"}`

### 7. Зарегистрировать webhook MAX

Webhook URL:

`https://<worker>.workers.dev/webhook`

В PowerShell на своём компьютере:

```powershell
$token = "ВАШ_ТОКЕН_MAX"
$secret = "ТОТ_ЖЕ_WEBHOOK_SECRET"
$url = "https://<worker>.workers.dev/webhook"
$body = @{
  url = $url
  update_types = @("bot_started","message_created","message_callback")
  secret = $secret
} | ConvertTo-Json
Invoke-RestMethod -Method Post `
  -Uri "https://platform-api.max.ru/subscriptions" `
  -Headers @{ Authorization = $token } `
  -ContentType "application/json" `
  -Body $body
```

MAX должен вернуть `success: true`.

### 8. Проверить бота

Откройте бота в MAX и нажмите Start или отправьте `/start`.

Ожидаемая последовательность:

1. выбор `Учитель` / `Ученик / родитель`;
2. выбор фамилии или класса;
3. главное меню;
4. `Сегодня` показывает расписание;
5. `Изменения` показывает только изменённые уроки;
6. `Оповещения` показывает актуальное школьное сообщение.

## Секреты

Никогда не добавляйте настоящий `BOT_TOKEN`, `WEBHOOK_SECRET` или приватный API key в GitHub. Используйте Cloudflare Secrets.

## Health-check

`GET /health` не раскрывает секреты и подходит для проверки доступности Worker.

## Webhook

Worker принимает только:

`POST /webhook`

Если заголовок `X-Max-Bot-Api-Secret` неверный, возвращается HTTP 403.

## Автоматические уведомления

Cron запускается каждую минуту и читает только небольшой лист `Статус_публикации`. Когда у какой-то даты (сегодня или до двух недель вперёд) меняется время публикации, Worker один раз загружает `Изменения`, `Изменения_учителей` и `Учителя`, собирает для каждого подписчика его личные изменения на эту дату и отправляет уведомление, только если они изменились с прошлого раза. Если изменения для класса или учителя убрали, приходит сообщение «действует основное расписание». За один запуск отправляется не больше 40 сообщений (лимит бесплатного Cloudflare), остальные уходят через минуту.

Для учителя добавляется кнопка `✓ Увидел`. Подтверждение сохраняется в D1 и дублируется в существующий механизм `Просмотры_учителей` через Apps Script.

При первом обнаружении пользователя текущая версия считается базовой и задним числом не рассылается.
